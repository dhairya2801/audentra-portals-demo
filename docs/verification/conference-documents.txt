Workflow
1. Open Ada and Camila in separate tabs. The populated staff board contains real
   stored synthetic originals and persisted extraction results, awaiting approval.
2. Use the staff header's Reset demo button. Only the configured Ada document
   requirements/cards reset; unrelated cards, next steps, and history survive.
3. From Ada's Your next steps, open a document action directly. Use demo document
   or choose the matching downloaded PDF/JPEG/PNG. The backend stores it and checks
   its contents against the expected type. A transcript cannot satisfy passport.
4. Open the fresh staff card. The existing preview, four-column field table,
   processing selector, edit pencils, Activity and Workflow tabs remain. Fields
   initially show --. Choose Run Edward parsing to extract from the stored original.
5. Compare fields with the preview. Pencil edits save canonical corrections with
   the task's expected version, idempotency, and before/after audit evidence.
   Accept/correction field decisions also persist. Parsing does not approve the
   document, complete enrollment, award credit, or determine health eligibility.
6. Ask Edward which documents remain pending versus received/awaiting staff review.
   Both assistants read the same canonical requirements. Reset and repeat.

Backend behavior
Migration 0082 adds an explicit demo requirement mapping and superseded/archive
markers. Reset resolves the configured demo external reference to its stable ID,
takes the same per-student transaction lock as upload/attach/completion/review,
supersedes active document submissions, archives associated review-card membership,
cancels only scoped document-review work, and changes requirements back to ready.
The linked financial worksheet also returns to not_started. Originals, parse results,
decisions and audit history remain. No other student's records are deleted.
A delayed parser result sees its original superseded/rejected and cannot restore
an active card or satisfy a reset requirement. Repeated identical uploads reuse the
same requirement/digest submission; new originals reuse the requirement's card.

Uploads initially perform a bounded content-type check. Successful type checks
persist pending_staff with empty field values. The authorized staff parsing action
queues the existing worker; successful extraction remains needs_review/under_review.
Missing and low-confidence values remain empty or flagged. Corrupt originals remain
available with a safe unreadable error. Temporary failures can retry the same stored
original. There is one bounded automatic retry and no expensive fallback chain.

Canonical updatedAt versions reconcile mutation receipts with later server reads.
Student document/journey pages invalidate on existing SSE events and use a bounded
15-second visible-page fallback plus focus refresh. The staff board retains its
existing 10-second/focus refresh. Events cause refetches; payloads are not records.
Parsed fields and original bytes are not persisted in board localStorage.

actual ID gpt-6-luna; it is not an assumed public alias for a Codex agent name.

The classifier and extractor use strict structured output. Representative live
PDF/image extraction selected this small model. The local runtime meters both
parsing and Edward calls in backend artifacts/conference/spend.json, including a
conservative reservation for failures without usage. It refuses paid calls before
the $2 task cap is exceeded. No provider responses or keys are committed.
